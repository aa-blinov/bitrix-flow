# Безопасность

Приложение — надстройка над одним порталом Битрикс24. За логином живут данные
портала и OAuth-токен с правами приложения, поэтому модель угроз простая: кража
сессии, кража токена, чужие события в обработчике и вредный контент из задач.

## Что уже сделано

**Доступ.** Один общий логин и пароль из окружения, сравнение за постоянное
время, 5 попыток на IP за 15 минут (адрес берётся из `X-Real-IP` — заголовок
ставит прокси, `X-Forwarded-For` клиент подделывает). Кука сессии `HttpOnly`,
`Secure`, `SameSite=Lax`, живёт 8 часов. Подпись куки — HMAC-SHA256, плюс запись
в Mongo: выход удаляет её, и та же кука сразу перестаёт работать.

**Портал.** `member_id` берётся только из базы, никогда из заголовка или query,
поэтому подменить портал запросом нельзя. Прокси REST принимает лишь методы,
которыми пользуется интерфейс, а всё, что меняет данные, — только POST: при
`SameSite=Lax` GET-мутация сработала бы как CSRF по ссылке с чужого сайта.

**События.** Обработчик `/api/b24/handler` сверяет `application_token` за
постоянное время. Подхватить токен «с первого события» можно только в течение
часа после установки — иначе достаточно было знать `member_id`.

**Контент.** Ссылки и картинки из текста задач фильтруются по схеме
(`javascript:`, `data:text/html` отбрасываются). Вложения проксируются с
`nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`, и открываются
inline только для неисполняемых типов — иначе html из задачи выполнился бы на
нашем домене.

**Инфраструктура.** MongoDB без публичного порта, приложение ходит под
пользователем с `readWrite` на одной базе (root остаётся администратору).
Caddy добавляет HSTS, `nosniff`, `Referrer-Policy`, `frame-ancestors` (только
свой домен и порталы Битрикс24), `object-src 'none'`, `base-uri`, `form-action`.
Дамп базы шифруется AES-256 при заданном `BACKUP_PASSPHRASE`.

## Что осознанно не сделано

- **Токены портала в Mongo лежат открытым текстом.** Ключ шифрования всё равно
  жил бы на том же сервере, поэтому от доступа к машине это не защищает.
  Реальный сценарий — утечка дампа — закрыт шифрованием бэкапа.
- **Нет CSP для скриптов страницы.** Next инлайнит рантайм, для строгой политики
  нужен nonce на каждый ответ; сейчас защита от XSS держится на React и фильтрации
  ссылок.
- **Лимит попыток входа хранится в памяти процесса.** При рестарте счётчик
  обнуляется; для одного инстанса этого достаточно.

## Проверки

```bash
npm audit --omit=dev     # обязан быть чистым
```

CI гоняет gitleaks на каждый push. Секреты живут в `.env.local` (режим 0600) и
в репозиторий не попадают: в `mongo-init.js` пароля больше нет, он приходит из
окружения.

Нашли проблему — пишите в issue без деталей эксплуатации, подробности в личку
владельцу репозитория.
